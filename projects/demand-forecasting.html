Executive summary.

A scaled ridge model was selected over a random forest using a chronological validation window. On 192 held-out days, MAE was 6.241 versus 11.878 for a weekly seasonal-naive forecast. The nominal 90% interval achieved 84.4% empirical coverage, exposing a practical uncertainty limitation.

Question and data

Can one-day-ahead forecasts improve on weekly seasonality while reporting useful uncertainty? The study generates 1,200 daily demand observations with trend, weekly cycles, promotions known before each forecast, and serially correlated noise.

After a 28-day warmup, 700 rows fit the models, 140 select the candidate, 140 calibrate the interval radius, and 192 form the untouched test window. Each test forecast uses actual demand through the preceding day.

Pipeline and evaluation

The modular pipeline builds calendar terms, known promotion features, lags 1/7/14, and a seven-day rolling mean shifted before aggregation. A scikit-learn pipeline contains scaling and ridge fitting; validation compares it with a random forest.

Absolute residuals from the separate calibration period determine the finite-rank interval radius. A seven-day circular block bootstrap gives a descriptive 95% interval for test MAE: [5.54, 7.00].

Interpretation and limitations

RMSE was 7.657 demand units and mean interval width was 20.82. Empirical coverage was 84.4% against a 90% nominal target. This undercoverage is retained and reported.

Serial dependence and drift undermine the usual exchangeability condition for split-conformal coverage. The project supplies an empirical diagnostic, not guaranteed time-series coverage. Evaluation is rolling one-step forecasting, not a recursive multi-day forecast.

Reproducible delivery

Importable Python modules separate configuration, data validation, features, fitting, prediction, evaluation, artifact persistence, and orchestration. A thin command-line entry point matches the existing project conventions.

The repository includes a documented data contract, saved-model inference, mathematical and leakage checks, reference predictions, machine-readable metrics, and a manifest recording versions, configuration, and data fingerprints. CI tests Python 3.11 and 3.12 and reproduces held-out outputs.

Code access. The project repository is private. Source code, the complete design, and reproducibility artifacts are available on request.
