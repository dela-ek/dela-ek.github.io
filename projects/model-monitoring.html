Executive summary.

A frozen classifier is evaluated across six future windows. Feature monitoring alerts on the two covariate-shift windows; a later change in the outcome relationship evades those feature tests but triggers a performance alert once labels arrive.

Question and data

Which changes can feature monitoring detect, and when are outcome labels needed to recognize model deterioration?

Separate synthetic cohorts provide 5,000 training, 1,500 validation, and 2,000 reference rows. Six future windows contain 1,200 observations each. The first two windows match baseline, the next two shift one feature, and the final two reverse part of the conditional outcome relationship while restoring the original feature distribution.

Pipeline and evaluation

Validation Brier score selects logistic regression over a random forest. Reference data freeze feature baselines and a Brier alert threshold. Kolmogorov–Smirnov tests use Holm correction across six features within each window; population stability index provides descriptive effect size. Performance at monitoring time t uses only labels from t−1, never the current window's unavailable outcomes.

The selected model's reference Brier score is 0.1458, with a frozen alert threshold of 0.1858. Two feature-drift windows alert. One delayed-label performance alert detects deterioration from concept shift. The final window remains unscored because its labels are not yet available. Saved per-feature diagnostics and timestamped alert records make the timing auditable.

Assumptions and limitations

Holm adjustment applies within each window and does not provide a global repeated-monitoring false-alarm guarantee. The Brier increase threshold is an operational rule, not a calibrated hypothesis test. Drift alerts do not establish business harm or automatically justify retraining. The simulator does not model actual serving infrastructure or live event ingestion.

Reproducible delivery

Importable Python modules separate configuration, data validation, domain-specific transformations, modeling or estimation, evaluation, artifact persistence, and reporting. The command-line entry point reproduces the full study with documented dependencies and seed 42.

The private repository includes mathematical and data-contract tests, a data fingerprint, configuration and library versions, machine-readable metrics, result tables, and the evaluation report. CI runs Python 3.11 and 3.12 and checks that a fresh run reproduces the saved outputs.

Code access. Source code, the full analytical design, and detailed verification logs are available on request. The project repository is private.
