Executive summary.

The earlier portfolio had no supporting repository for its logistics claim, so this project was rebuilt without the unsupported latency statement. On a seeded synthetic dataset, item co-occurrence achieved 9.38% Hit Rate@5 versus 5.0% for global popularity.

Question and data

Can simple co-occurrence structure improve the chance of retrieving each user's next item? The generator creates category-oriented interaction histories for 320 simulated users and 80 items. Each user's final event is held out as the target.

Method

The popularity baseline recommends globally frequent unseen items. The candidate model scores unseen items by how often they co-occur with items in the user's history, then fills any remaining positions using popularity. Both methods return five recommendations.

Interpretation and limitations

The candidate retrieves more held-out items than popularity in this simulator, but absolute coverage remains modest. The result validates the evaluation pipeline and expected co-occurrence behavior—not business impact.

  • The data is synthetic and encodes category preference by construction.
  • No inventory, route, margin, service-level, cold-start, or latency constraints are modeled.
  • Production evaluation would require temporal data, offline ranking diagnostics, online tests, and explicit operational objectives.
Educational disclaimer. This project is illustrative and is not logistics, procurement, operational, or business advice. It has not been validated for production deployment.
