Executive summary.

The project models when customers churn while retaining the information in incomplete follow-up. On 1,200 test customers, the 12-month IPCW Brier score is 0.2199 versus 0.2515 for a training Kaplan–Meier baseline. Harrell concordance is 0.662.

Question and data

How can a model estimate churn risk when many customers have not completed follow-up? The simulator creates 6,000 customers with baseline engagement, support history, and price index. Monthly event times and independent censoring determine each observed duration.

Train, validation, and test sets are split by customer before monthly risk-set expansion. Censored customers contribute observed event-free months and then leave the risk set; they are never treated as lifetime non-churners.

Pipeline and evaluation

A pooled logistic model estimates monthly hazards from baseline features, month, and month squared. The product of one minus each hazard yields a bounded, nonincreasing survival curve. Validation selects between two regularization strengths.

Training-only censoring estimates weight the held-out 12-month Brier score. A training Kaplan–Meier curve supplies the baseline. The modular package persists the fitted predictor and supports batch survival scoring.

Interpretation and limitations

Test censoring is 55.8%. The model improves the censoring-adjusted Brier score relative to the cohort baseline, while the calibration plot compares predicted risk with held-out Kaplan–Meier estimates by risk quintile.

Marginal censor weights assume independent censoring and sufficient follow-up support. Harrell concordance is censoring-sensitive, and calibration has no confidence bands. This predictive model does not estimate the causal effect of a retention intervention.

Reproducible delivery

Importable Python modules separate configuration, data validation, features, fitting, prediction, evaluation, artifact persistence, and orchestration. A thin command-line entry point matches the existing project conventions.

The repository includes a documented data contract, saved-model inference, mathematical and leakage checks, reference predictions, machine-readable metrics, and a manifest recording versions, configuration, and data fingerprints. CI tests Python 3.11 and 3.12 and reproduces held-out outputs.

Code access. The project repository is private. Source code, the complete design, and reproducibility artifacts are available on request.
