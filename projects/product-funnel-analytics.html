Executive summary.

SQL transformations measure seven-day conversion at 21.57% among 11,412 mature users, with Wilson 95% interval [20.83%, 22.34%]. Day-7 retention is 28.27% among 11,337 users with complete follow-up.

Question and data

Where do users leave an ordered purchase funnel, and how do conversion and retention differ by mature signup cohort?

The generator creates 12,000 signups across four months, acquisition channels, ordered view/cart/checkout/purchase events, and day-7 returns. The extract deliberately includes duplicate event IDs and events beyond the May 1, 2026 cutoff.

Pipeline and evaluation

SQLite common-table expressions and indexed relational joins enforce chronological funnel steps within seven days of signup. Eligibility is calculated from the data cutoff. Day-7 retention uses visits in [signup + 7 days, signup + 8 days), with a separate eight-day maturity denominator. Python handles validation, loading, confidence intervals, reporting, and artifact export; the analytical transformations run in SQL.

The ordered funnel contains 11,412 views, 6,299 carts, 3,883 checkouts, and 2,462 purchases. Cleaning removes 287 exact duplicate events and excludes 293 events after cutoff. Cohort/channel tables, executable SQL, and a regenerated SQLite database make the counts auditable.

Assumptions and limitations

Channel differences are descriptive and may reflect acquisition mix rather than channel effects. The synthetic event process is simplified. Independent-user binomial intervals do not account for clustered acquisition or repeated experiments. Identity resolution, timezone conversion, revenue reconciliation, and event-latency correction need additional production rules.

Reproducible delivery

Importable Python modules separate configuration, data validation, domain-specific transformations, modeling or estimation, evaluation, artifact persistence, and reporting. The command-line entry point reproduces the full study with documented dependencies and seed 42.

The private repository includes mathematical and data-contract tests, a data fingerprint, configuration and library versions, machine-readable metrics, result tables, and the evaluation report. CI runs Python 3.11 and 3.12 and checks that a fresh run reproduces the saved outputs.

Code access. Source code, the full analytical design, and detailed verification logs are available on request. The project repository is private.
